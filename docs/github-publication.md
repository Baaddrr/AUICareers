# Preparing the repository for GitHub

This prepared repository includes the project source and documentation. Preparation added environment-based configuration, the missing Flask-Login dependency, `.env.example`, and `.gitignore`. Other application behavior is unchanged.

## Repository contents

Publish the first-party source, templates, dependency manifest, and documentation. Exclude the ZIP's virtual environment, bytecode, and nested Git directory. If importing into an existing repository, retain that repository's own `.git` directory rather than copying the archive's metadata over it.

The following is a suggested root `.gitignore`:

```gitignore
# Local Python environments and generated files
.venv/
venv/
__pycache__/
*.py[cod]
.pytest_cache/
.coverage
htmlcov/

# Local configuration and data
.env
.env.*
!.env.example
instance/
*.log
*.sqlite
*.sqlite3

# Editor and operating-system files
.idea/
.vscode/
.DS_Store
Thumbs.db
```

An ignore rule does not remove files already tracked by Git. Check the staged changes before pushing.

## Credentials and history

The original archive embedded database credentials and a fixed Flask session secret. The prepared `config.py` reads protected environment variables instead, as described in [Local setup](setup.md). Do not copy the original values into examples, issues, or screenshots.

If the credentials are real or reused, replace them wherever they are valid. Review Git history as well as the current files: deleting a secret from the latest version does not remove it from earlier commits. This review did not establish whether any credential in the archived history remains valid.

## Publication checklist

- Place `README.md`, `CONTRIBUTING.md`, and `docs/` at the application repository root.
- Replace embedded secrets and verify that no real personal data, database exports, or local environment files are staged.
- Exclude the bundled `venv/` and generated bytecode.
- Keep setup limitations visible until the source changes and database migrations are complete.
- Choose a license with the other project authors before adding a `LICENSE` file.
- Review the externally hosted homepage image's usage rights or replace it with an asset you can publish.

GitHub publication and application hosting are separate actions. Publishing the source does not deploy the Flask application or resolve its runtime security issues.
